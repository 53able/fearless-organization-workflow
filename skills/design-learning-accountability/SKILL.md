# 目的・基準・目標圧力の設計

## 必要な入力

目的・受益者、品質と倫理・安全の基準、目標・期限、技術・需要・資源・技能、報酬と処分の条件、現場の反証、相談先、変更の判断権者。

## 手順

1. [目標と戦略の点検](references/principles.md)を読み、仕事の不確実性・相互依存・結果の影響を示す。方向を示す責任と、現場の知識を求める必要を開始説明に入れる。
2. 目的・受益者、品質・倫理・安全の基準、目標・期限を分ける。高い基準を維持しつつ、暫定的な懸念・未達・援助要請を早く扱う条件を具体化する。
3. 正当な手段で目標を達成できる前提を技術・顧客需要・資源の証拠から点検する。報酬・評価・処分が懸念報告や戦略修正を罰していないか、明示規則と現場経験を照合する。
4. 未達について技能、努力、支援、資源、戦略の仮説を比較する。全員免責にも個人責任への即断にも進まず、それぞれを支持・反証する情報を整理する。
5. 支援追加、業務・指標・報酬条件の見直し、戦略修正を比較し、権限者へ変更判断を返す。無承認の目標引下げや制度変更を実施済みにしない。
6. [開始説明と矛盾表](assets/template.md)に現場の反証、見直し条件、担当を残す。未知の成立条件を試すなら `design-intelligent-experiments`、負担・育成なら `design-employee-care-practices`、監督の利益相反なら `review-reporting-and-fair-boundaries` へ。

## 境界と完了条件

共有可能な最小限の情報を使い、氏名・少人数から特定できる情報は必要に応じて役割名へ置き換える。共有範囲・本人の意向が不明なら公開・送信を保留し、限定した下書きを作る。匿名性や報復がないことを保証しない。

未知の経験・過去の応答・判断権者を補完せず「未確認」とする。資料整理の権限だけで制度変更・処分・採否を承認済み／実施済みにしない。権限者の判断が必要な箇所と、今できる準備を分ける。

成果物に担当・期限または再確認条件・共有範囲が入り、事実と仮説が区別できたら資料作成を完了する。対話・制度改善そのものの完了とは区別する。必要条件が欠ける場合は該当判断を保留し、確認先・未解消事項を残す。
