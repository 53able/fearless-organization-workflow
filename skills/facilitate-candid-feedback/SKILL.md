# 率直なレビューとフィードバック

## 必要な入力

対象・目的・開発段階、決定権者、参加者の専門性、レビューの範囲、観察された言動・影響、本人が確認できる情報、共有範囲。

## 手順

1. [レビューと行動対話の原則](references/principles.md)を読み、成果物の改善か、貢献を妨げる行動への対話かを選ぶ。加害申告なら通常レビューを止め `review-reporting-and-fair-boundaries` に返す。
2. 成果物レビューでは目的と段階を合わせ、問題・根拠・解決候補に整理する。未完成さを本人の能力不足と同一視せず、専門性の異なる視点を集める。
3. 行動への対話では観察した言動、仕事・参加への影響、確認したい解釈、具体的な変更依頼を分ける。意図や人格を決めつけず、本人の説明を聞く余地を残す。
4. 異論の内容・根拠・確度を検討する。不人気であることを違反・無能の根拠にせず、合意できない部分も記録する。率直さを侮辱や個人情報の公開の口実にしない。
5. 提案と指示を区別し、採否と次の行動を対象の責任者へ返す。助言者が決定権を奪わず、採用しない場合も理由と確認条件を残す。
6. [記録または対話案](assets/template.md)に担当・再確認条件を入れる。吊し上げや人格攻撃が始まったら進行を止め、共有範囲を限定して課題へ戻す。対話が傷ついた場合は `renew-psychological-safety` に修復の未解消事項を渡す。

## 境界と完了条件

共有可能な最小限の情報を使い、氏名・少人数から特定できる情報は必要に応じて役割名へ置き換える。共有範囲・本人の意向が不明なら公開・送信を保留し、限定した下書きを作る。匿名性や報復がないことを保証しない。

未知の経験・過去の応答・判断権者を補完せず「未確認」とする。資料整理の権限だけで制度変更・処分・採否を承認済み／実施済みにしない。権限者の判断が必要な箇所と、今できる準備を分ける。

成果物に担当・期限または再確認条件・共有範囲が入り、事実と仮説が区別できたら資料作成を完了する。対話・制度改善そのものの完了とは区別する。必要条件が欠ける場合は該当判断を保留し、確認先・未解消事項を残す。
