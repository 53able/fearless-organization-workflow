# 知的な実験と撤退判断

最難関の未知を先に確かめ、終了を含む判断と学習の引継ぎを実験前から設計する。

## 必要な入力

仮説、解きたい問題、最難関、技術・利用・経済性の条件、既存知識、損失上限、実行承認の範囲、評価制度、共有許可。

## 権限・守秘

共有を許された必要最小限の情報を使い、氏名・所属・細かな日時の組合せによる再識別を避ける。共有範囲や同意が不明なら識別情報を省いた草案にとどめ、公開・送信しない。確認できない経験・過去の応答・判断権者を補作せず、不明と結論の保留範囲を書く。資料作成の権限を制度変更・実行・処分の権限に読み替えない。提案・承認待ち・実施確認済みを区別し、専門判断は実際に権限を持つ人へ返す。

## 手順

1. 既知の知識と未検証の仮説を分ける。既に否定された案なら、何の条件が変わったかを確認し、学びのない再試行を提案しない。
2. [実験原則](references/principles.md)を読み、案が成立しない理由を先に列挙する。技術が動く、利用者が使う、費用や資源が持続する、という成立条件を別に置く。
3. 成立を最も左右する未知を選び、それを反証しうる最小の試験を設計する。仮説、観測方法、範囲、期間、比較条件、解釈の限界を明記する。
4. 実験前に継続・変更・終了の条件と損失上限を置く。金額・時間・安全・影響範囲の上限と停止判断者を確認する。上限や権限が未定なら実行を保留し、計画案のみ作る。
5. 結果を各成立条件に照合する。技術成功で利用や経済性の不成立を覆い隠さず、計測不足と否定的結果を区別する。結果を見た後の条件変更は理由と承認を記録する。
6. [実験計画票](assets/template.md)に判断案、学んだこと、適用できない範囲、終了後の知識・資源の引継ぎを作る。失敗件数や中止件数を目標にせず、不確実性を減らした価値を示す。

## 保留・停止・引継ぎ

撤退を罰する評価制度は[学習と責任](../design-learning-accountability/SKILL.md)と[従業員への配慮](../design-employee-care-practices/SKILL.md)へ判断材料を返す。既知の手順違反は[失敗分析](../learn-from-failures/SKILL.md)と[公正な境界](../review-reporting-and-fair-boundaries/SKILL.md)へ。安全違反を実験として扱わず、無承認の実行・資源再配置はしない。終了案の提出と実際の終了を区別する。
