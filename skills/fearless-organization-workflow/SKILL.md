# 統合・進行管理

心理的安全性を宣言や会議開催で完了させず、必要な情報が届き、検討され、仕事の改善へ使われる運用を設計する。安全性の認証や成果保証は行わない。

## 入力

課題、具体的な観測、関係する集団・時点、仕事の目的、利用者の権限、既存の対応制度、機微情報と共有範囲を確認する。不足していても安全に作れる整理案は進め、判断に必要な不足だけを確認する。

## 手順

1. 緊急危険、加害申告、報復懸念を先に切り分ける。既存の専門対応へ接続し、台帳作成や全員合意を待たせない。申告案件を一般会議の議題へ転用しない。
2. 観測事実と解釈を分け、対象を集団・時点ごとに限定する。[共通原則](references/common-principles.md)で概念と権限の境界を確認する。
3. [振り分け表](references/routing.md)から、今の判断に必要な専門スキルだけを選ぶ。固定の全工程や全14個の呼出しにはしない。専門スキルの利用は、別エージェント起動や外部操作の許可ではない。
4. 各課題について成果物、判断権者、実行担当、返答担当、必要情報、期限または事象による再確認条件を置く。未確認の担当を実在すると扱わない。
5. 場づくり（目的・不確実性・依存関係）、招請（問い・参加経路）、応答（受領・検討・判断・返答）のどこが途切れているか確認する。説明や質問だけで、放置や資源不足を解決したことにしない。
6. [台帳テンプレート](assets/template.md)へ記録する。同じ未解消事項のID、保留理由、共有範囲を引継ぎ先にも残す。担当が変わっただけで解消扱いにしない。
7. 現場の反応と実際の対応を確認し、必要なら専門スキルへ戻る。引継ぎは受信と対応の見通しまで、改善は当事者の経験と仕事への影響まで確認する。確認できなければ「提案済み」「判断待ち」「再確認待ち」として終了する。

## 保留・停止・権限

- 情報不足は仮説で補い、事実と混ぜない。尺度の原仕様が未確認なら採点を保留する。
- 処分、法的責任、採用・雇用、専門安全判断、制度変更の決裁は権限者に返す。資料作成を承認や実施として報告しない。
- 本人の識別情報は必要最小限にし、共有範囲が不明な資料の公開・送信を進めない。匿名性・報復防止・他者の変化を保証しない。
- 対話を続けることで危険や不利益が増す場合は、公開対話を止めて適切な相談経路の確認へ移る。

## 共通引継ぎ

専門成果物に「観測事実／解釈・仮説／不足情報／必要な人の判断／次の担当／未解消事項／再確認条件／共有範囲」を付ける。不要な欄は理由を示して対象外とし、架空の情報で埋めない。
