# 失敗分析と工程学習

失敗を暫定分類し、各役割が当時見えていた情報から工程の改善案と再確認計画を作る。

## 必要な入力

時系列、当時利用できた知識、既知の手順、役割、実害、応急措置、過去の類似事象・学習、共有許可。

## 権限・守秘

共有を許された必要最小限の情報を使い、氏名・所属・細かな日時の組合せによる再識別を避ける。共有範囲や同意が不明なら識別情報を省いた草案にとどめ、公開・送信しない。確認できない経験・過去の応答・判断権者を補作せず、不明と結論の保留範囲を書く。資料作成の権限を制度変更・実行・処分の権限に読み替えない。提案・承認待ち・実施確認済みを区別し、専門判断は実際に権限を持つ人へ返す。

## 手順

1. 対象と期間を限定し、発生・検知・対応・復旧の時系列を作る。観測と後から判明した情報を分け、当時知らなかった情報で行動を裁かない。
2. [分類原則](references/principles.md)を読み、防止可能・複雑・知的の候補と根拠を置く。結果の大小だけで分類せず、既知の手順、相互作用、新規性、試験の設計を確認する。不足なら分類保留とする。
3. 工程に接した各役割の観察・制約・行動を並べる。「なぜそうしたか」を当時の条件から調べ、単一の根本原因や個人の怠慢を補作しない。
4. 応急復旧と恒久改善を別行にする。借用、迂回、手作業が不足・危険・負担を他部門や次の勤務へ移したか確認する。復旧成功だけで改善完了にしない。
5. 分類に応じて予防・訓練・工程再設計、多視点での接続改善、または仮説修正と次の試験を提案する。学習済みの同一失敗を新規探索として再試行しない。
6. [分析票](assets/template.md)に改善担当、必要な承認、再発と副作用の観測条件を記入する。報告・分析を終えたことと、改善が有効だったことを区別して引き継ぐ。

## 保留・停止・引継ぎ

違反や公正な境界の判断は[独立した申告経路](../review-reporting-and-fair-boundaries/SKILL.md)へ、未知を試す次の計画は[知的な実験](../design-intelligent-experiments/SKILL.md)へ。緊急対応が続いているなら分析を保留し既存対応を優先する。原因の確定・責任認定・処分はこのスキルで行わない。
