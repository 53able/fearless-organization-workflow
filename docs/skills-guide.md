# スキルの使い方と選び方

このスキル群は、職場で質問・異論・援助要請・失敗報告を扱うための判断資料や運用案を作ります。統合スキル1個と専門スキル14個で構成され、専門スキルは単独でも使えます。

複数の課題が絡むときは `fearless-organization-workflow`、扱いたい課題が決まっているときは該当する専門スキルを選びます。全15個を順番に実行する必要はありません。

## 最初の依頼

導入方法は [README](../README.md#導入) を参照してください。Codexでは `$スキル名` と依頼内容を組み合わせます。

```text
$fearless-organization-workflow
開発チームでは会議後に異論が出ます。以前の懸念には返答がありません。
私は会議の進行担当で、評価制度を変更する権限はありません。
個人名は使わず、課題の整理と担当・再確認条件のある改善案を作ってください。
```

依頼には次の情報があると、具体的な案を作りやすくなります。分からない項目は「未確認」と記載できます。

| 情報 | 記載例 |
|---|---|
| 対象と時点 | 開発チームの直近2週間の定例会議 |
| 観測と経験 | 会議後に別の案が出た。報告後の返答がない |
| 仕事の目的 | 設計の見落としを減らし、判断理由を共有したい |
| 自分の権限 | 進行と資料整理はできる。制度変更はできない |
| 共有範囲 | 個人名は省く。公開せず自分用の下書きにする |
| ほしい成果物 | 会議進行案、警告検討票、改善台帳など |

機微な経験を詳述する必要はありません。資料の下書き作成と、他者への送信・調査・制度変更の実行は別の依頼として扱います。

## 統合・進行管理

**呼出し:** `$fearless-organization-workflow` · [スキル本体](../skills/fearless-organization-workflow/SKILL.md) · [テンプレート](../skills/fearless-organization-workflow/assets/template.md)

課題を分類し、必要な専門スキル、判断権者、実行・返答担当を整理します。目的の説明、参加の招請、実際の応答のどこが途切れているかを確認し、未解消事項を台帳で追跡します。

**依頼例:** 「会議では異論が出ず、警告には返答がありません。業務量も過大です。私の権限は進行と資料整理だけです。必要な担当を選び、改善台帳を作ってください。」

単純な返信や一つの課題には、その専門スキルを直接使えます。振り分けは別エージェントの自動起動や外部操作の許可ではありません。

## 1. 概念と適用条件の整理

**呼出し:** `$clarify-psychological-safety` · [スキル本体](../skills/clarify-psychological-safety/SKILL.md) · [テンプレート](../skills/clarify-psychological-safety/assets/template.md)

信頼・親切・同意・性格・満足と心理的安全性を区別します。具体的な場面、本人が予想する反応、仕事の条件をもとに、混同と不足情報を整理します。高い成果基準と質問のしやすさを別軸で扱います。

**依頼例:** 「上司の専門性を信頼していますが、質問すると無能と思われそうで怖いです。何が違うのか整理してください。」

性格診断や全社の安全性の一律判定は行いません。具体的な状態を測定したい場合は13へつなぎます。

## 2. 発言障壁の分析

**呼出し:** `$analyze-voice-barriers` · [スキル本体](../skills/analyze-voice-barriers/SKILL.md) · [テンプレート](../skills/analyze-voice-barriers/assets/template.md)

印象管理、地位差、関係悪化、不利益、徒労感、暗黙ルールを分けます。言いにくい内容、相手、過去の応答をもとに、発信者の言い方に加えて受け手・場・相談経路の改善候補を作ります。

**依頼例:** 「問題を報告しても返答がなく、『言っても変わらない』と言われています。障壁と受け手側の改善を整理してください。」

発言や自己開示を強制しません。放置された報告は6、報復や加害の疑いは10へつなぎます。

## 3. 目的・基準・目標圧力の設計

**呼出し:** `$design-learning-accountability` · [スキル本体](../skills/design-learning-accountability/SKILL.md) · [テンプレート](../skills/design-learning-accountability/assets/template.md)

仕事の目的、高い基準、目標・期限、報酬・処分、技能・需要・資源を照合します。正当な手段で達成できるかを点検し、開始説明、矛盾の整理、支援と見直し条件を作ります。

**依頼例:** 「倫理研修は済んでいますが、正当な営業手段では販売目標に届きません。目標・評価・支援の矛盾を点検してください。」

未達を一律に免責したり、根拠なく目標を下げたりしません。仮説を試す必要があれば8、負担や資源不足は12へつなぎます。

## 4. 質問・傾聴・参加の設計

**呼出し:** `$design-inquiry-and-participation` · [スキル本体](../skills/design-inquiry-and-participation/SKILL.md) · [テンプレート](../skills/design-inquiry-and-participation/assets/template.md)

議題、既知・未知、必要な経験者、権力差、時間・言語・守秘条件に合わせて参加を設計します。具体的な限界を示す招請文、誘導しない質問、理解確認、採否を返す進行案を作ります。

**依頼例:** 「会議で上位者だけが話します。順番発言が負担になる参加者もいます。見送りや別経路のある進行案を作ってください。」

全員の発言を義務にせず、国籍から形式を決めません。声が出ない理由は2、排除や意見利用の問題は11で扱います。

## 5. 率直なレビューとフィードバック

**呼出し:** `$facilitate-candid-feedback` · [スキル本体](../skills/facilitate-candid-feedback/SKILL.md) · [テンプレート](../skills/facilitate-candid-feedback/assets/template.md)

成果物のレビューと行動へのフィードバックを分けます。前者は問題・根拠・解決候補、後者は観察した言動・影響・確認したい解釈・変更依頼を整理し、異論と判断者を残します。

**依頼例:** 「不人気な案を無能の証拠として扱う発言がありました。案の内容を検討できるレビューと進行文を作ってください。」

助言者が決定権を奪うことや人格攻撃を認めません。加害申告は10、傷ついた対話の修復は14へつなぎます。

## 6. 警告・悪い知らせへの対応

**呼出し:** `$respond-to-warnings` · [スキル本体](../skills/respond-to-warnings/SKILL.md) · [テンプレート](../skills/respond-to-warnings/assets/template.md)

観測、懸念する害、確度、報告履歴、既存経路を整理します。発言への謝意と内容への同意を分け、確認可能な問い、防護・追加確認・保留・却下の判断候補、再提起と返答を設計します。

**依頼例:** 「異常の報告を受けましたが証拠は曖昧です。専門担当への確認事項と、報告者への初動応答案を作ってください。」

証拠不足を虚報や無害の証明にしません。緊急時は既存の専門対応を優先し、文書完成を待たせません。経路の利益相反は10へつなぎます。

## 7. 失敗分析と工程学習

**呼出し:** `$learn-from-failures` · [スキル本体](../skills/learn-from-failures/SKILL.md) · [テンプレート](../skills/learn-from-failures/assets/template.md)

時系列、当時の知識、手順、役割、実害、応急措置をもとに分析します。防止可能・複雑・知的な失敗を暫定分類し、各役割の制約、応急復旧と恒久改善、再発と副作用の確認計画を作ります。

**依頼例:** 「他部署の資材を借りて復旧しましたが、借用先が不足で止まりました。負担移転を含めた失敗分析案を作ってください。」

結果だけで責任を認定せず、分類に必要な情報がなければ保留します。未知を試す次の計画は8、公正な違反対応の判断は10へつなぎます。

## 8. 知的な実験と撤退判断

**呼出し:** `$design-intelligent-experiments` · [スキル本体](../skills/design-intelligent-experiments/SKILL.md) · [テンプレート](../skills/design-intelligent-experiments/assets/template.md)

仮説、最難関、既存知識、技術・利用・経済性、損失上限、承認範囲を整理します。最重要の未知を小さく試す計画と、継続・変更・終了条件、終了時に残す学びを作ります。

**依頼例:** 「技術は動きますが運用費が売上を超えています。追加投資は未承認です。次の確認と継続・終了の判断条件を作ってください。」

技術成功だけで事業の成立を判断せず、無承認で実験を実行しません。撤退を罰する評価制度は3・12へつなぎます。

## 9. 協働・引継ぎ・相互学習

**呼出し:** `$design-teaming-and-knowledge-sharing` · [スキル本体](../skills/design-teaming-and-knowledge-sharing/SKILL.md) · [テンプレート](../skills/design-teaming-and-knowledge-sharing/assets/template.md)

依存関係、役割、必要知識、時間・時差・言語、指揮系統をもとに、時間制約下の交信と日常の知識交換を分けて設計します。受領・実行不能・更新の確認や、援助要請・同僚間教育・再利用の運用を作ります。

**依頼例:** 「教材を増やしても質問できず使われません。拠点間の引継ぎも受領不明です。応答と利用確認まで含む運用案を作ってください。」

送付や交流会の開催だけで完了としません。専門指揮は代行せず、学習時間の不足は12へつなぎます。

## 10. 独立した申告経路と公正な境界

**呼出し:** `$review-reporting-and-fair-boundaries` · [スキル本体](../skills/review-reporting-and-fair-boundaries/SKILL.md) · [テンプレート](../skills/review-reporting-and-fair-boundaries/assets/template.md)

本人の希望と共有範囲、既存規則、推進・情報提供・審査・決裁・評価の役割を点検します。利益相反や情報依存の図、確認できた相談経路、不利益懸念の追跡、保護・調査・判断の引継ぎ資料を作ります。

**依頼例:** 「申告先が当事者の評価者でもあります。本人は不利益を恐れ、転送同意も未確認です。経路と確認事項を整理してください。」

独立した窓口の存在や匿名性を保証せず、最終認定が未確定でも保護の検討は止めません。有罪認定・制裁・法的判断は権限者へ返します。

## 11. 多様性・包摂・所属感

**呼出し:** `$design-inclusive-contribution` · [スキル本体](../skills/design-inclusive-contribution/SKILL.md) · [テンプレート](../skills/design-inclusive-contribution/assets/template.md)

構成の多様性、実際の参加と意見利用、本人の所属感を分けます。一つの意思決定を追い、必要な知識、参加・提出経路、採否と応答、アクセス不足や代表役の負担を整理します。

**依頼例:** 「多様な人を会議に招待しましたが、特定の人の意見が一度も検討されません。参加と意見利用のマップを作ってください。」

招待人数で包摂を判定せず、本人不在で所属感を断定しません。対話形式は4、資源・慣行は12、加害・報復は10へつなぎます。

## 12. 従業員への配慮の制度化

**呼出し:** `$design-employee-care-practices` · [スキル本体](../skills/design-employee-care-practices/SKILL.md) · [テンプレート](../skills/design-employee-care-practices/assets/template.md)

仕事量、支援の利用条件、負担配分、育成・学習時間、処遇・監視等の慣行、変更権限と予算を点検します。支援追加、業務削減・再配分、慣行変更を比較し、他者への負担移転と再確認計画を示します。

**依頼例:** 「意見を聞く時間も取れない業務量です。質問研修を追加する前に、仕事量と支援制度の変更候補を整理してください。」

対話の善意で資源不足を埋めず、予算や権限がなければ判断待ちにします。雇用・報酬・労務の最終決定は行いません。

## 13. 測定・聞き取り・証拠解釈

**呼出し:** `$assess-psychological-safety-evidence` · [スキル本体](../skills/assess-psychological-safety-evidence/SKILL.md) · [テンプレート](../skills/assess-psychological-safety-evidence/assets/template.md)

尺度の版・原文・翻訳変更履歴・回答方向・逆転項目・集計仕様と、対象集団・時点・守秘条件を確認します。測定計画、採点仕様の確認事項、聞き取り・仮想場面案、報告データの複数解釈を作ります。

**依頼例:** 「受付制度変更後に報告が30件から60件になりました。実害は不明です。改善を判断するために必要な追加観測を整理してください。」

原仕様が不明なら採点を保留します。発言数による診断、独自の閾値や検証済み翻訳の創作、因果効果の断定は行いません。

## 14. 修復・練習・継続改善

**呼出し:** `$renew-psychological-safety` · [スキル本体](../skills/renew-psychological-safety/SKILL.md) · [テンプレート](../skills/renew-psychological-safety/assets/template.md)

具体的な言動と影響、自分の権限、本人の希望、未完了事項、支援・報復への懸念を整理します。謝罪・撤回・やり直し案、発信と受信の練習、集団・時点ごとの点検計画を作ります。

**依頼例:** 「質問を遮ったことは謝罪しましたが、評価が下がるという懸念が残っています。修復対話と継続点検を設計してください。」

謝罪だけで修復完了にせず、許しや自己開示を求めません。報復・加害は10、制度や資源の問題は12へ戻します。

## 似ているスキルの使い分け

| 組合せ | 選び方 |
|---|---|
| 1と13 | 概念の混同を解くなら1。測定方法やデータの解釈を扱うなら13 |
| 2と4 | 声が出ない条件を調べるなら2。問い・傾聴・参加形式を作るなら4 |
| 5と14 | 内容や行動の改善を伝えるなら5。傷ついた対話のやり直しと追跡なら14 |
| 6と7 | 現在の懸念への受領・確認・返答なら6。事後の工程分析と再発対策なら7 |
| 7と8 | 起きた失敗の分析なら7。未知を試す次の計画と終了判断なら8 |
| 3と12 | 目的・目標・評価の前提なら3。業務量・支援・育成の実際の利用条件なら12 |
| 4と11 | 参加の形式なら4。誰の知識が検討され使われるかなら11 |

## 成果物を次の行動へつなぐ

各スキルには成果物テンプレートがあり、共通して次の8項目を残します。

| 項目 | 読み取ること |
|---|---|
| 観測事実 | 何が起きたか。直接観察・申告・伝聞の違い |
| 解釈・仮説 | どんな説明が考えられるか。まだ確定していないこと |
| 不足情報 | 判断に必要な未確認事項と確認先 |
| 必要な人の判断 | 何を誰の権限で決める必要があるか |
| 次の担当 | 誰が次に何を行い、返答するか |
| 未解消事項 | 残る懸念・異論・保留理由。台帳では元のIDを維持 |
| 再確認条件 | いつ、または何が起きたら見直すか |
| 共有範囲 | 誰が閲覧し、何を記載し、再共有できるか |

たとえば「警告を受領した」後も、検討担当や返答が不明なら未解消です。「提案済み」「判断待ち」「実施中」「再確認待ち」「確認済み」を区別し、資料ができたことと改善が確認できたことを分けて使います。

緊急危険や申告案件では、既存の専門対応を優先します。通常の会議・測定・帳票の完成を待たせません。スキルは心理的安全性の認証、匿名性や報復防止の保証、制度の無権限変更、専門安全・法務・人事判断の代行を行いません。
