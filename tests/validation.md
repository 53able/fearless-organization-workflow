# 検証記録

実装対象は統合1個・専門14個。各スキルに本体、判断原則、成果物テンプレート、UIメタデータを用意した。スキル本文と参照資料に出典・URL・取得元の全文を含めていない。

## 構造と導入

- 公式 `skill-creator/scripts/quick_validate.py`：15個すべて成功。システムPythonのPyYAML不足は、`uv run --with pyyaml` の一時的な検証環境で解消した。プロジェクトの実行依存は追加していない。
- `node scripts/validate-suite.mjs`：15個、相対リンク、UI呼出し、8項目の引継ぎ、76件のシナリオ定義を検査して成功。
- UI YAML：15個すべて構文解析に成功。短い説明の長さと各スキルへの呼出しを確認。
- `node tests/install-suite.test.mjs`：15個の導入、再実行、同名既存フォルダの保存と部分導入防止を確認。
- `~/.codex/skills` の15リンク：完成したスキルへ解決されることを確認。
- Vercel `skills` CLI v1.7.0：`npx skills add . --list` で15個検出。隔離した一時プロジェクトで `--skill '*' --agent codex --yes` による15個の導入に成功。`SKILL.md`、`references/`、`assets/`、`agents/` の保持を確認。

Vercel互換性は配布用の `skills/<name>/SKILL.md` と必須の `name`・`description`、CLIでの検出と導入について確認した。CLI本体のNode/TypeScriptプロジェクトを複製する必要はない。特定のエージェントが任意のUIメタデータを表示することまではこの検証の対象にしない。

## 独立した実行テスト

作成担当と異なる担当が実際のスキルと参照資料を読み、隔離ディレクトリで15件の依頼に対する成果物を生成した。評価者には期待解を渡さず、実際の成果物を統合担当が読んで下表を確認した。成果物の生成以外の送信・制度変更・収集・実験実行はしていない。
